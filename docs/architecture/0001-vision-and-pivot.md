# 0001: Vision — the Aethyro NTG Engine, and why this isn't a vertical bet

**Status:** Accepted.

## Context

**Where this came from.** The founder's prior effort ([leerobber/Firmament](https://github.com/leerobber/Firmament)) had decided its first vertical (air-gapped legal/compliance document review, Firmament ADR 0001/0003) before any kernel code existed. On reflection, the founder decided not to start there: a vertical-first bet risked building sales/compliance-specific plumbing before there was any genuinely new technology underneath it. This repository (`aethyro-ntg`) is that reset — build the novel engine first, let the vertical/product question follow from what the engine can actually do.

**What "novel" actually means here — checked, not assumed.** An early draft of this plan (produced in a separate, external AI session, never merged into this or the Firmament repo) proposed a "Neural Ternary Graph (NTG) Engine" and described it as combining three "world first" elements: ternary weights, graph-structured networks, and self-modifying architecture. Before adopting that framing, each claim was checked against real literature (2026-07-07):

- **Ternary weight quantization is not new.** Microsoft's BitNet b1.58 constrains weights to {-1, 0, +1}, achieving ~90% memory savings vs. FP16, and shipped a 2B-parameter model trained on 4 trillion tokens under the MIT license (BitNet b1.58 2B4T, April 2025), with further CPU optimizations in January 2026. This is proven, production-grade, and open. ([BitNet b1.58 2B4T Technical Report](https://arxiv.org/pdf/2504.12285), [1.58-bit LLM — Wikipedia](https://en.wikipedia.org/wiki/1.58-bit_large_language_model))
- **Self-modifying / dynamically-evolving graph topology is not new.** This is an active 2025-2026 research area: self-organizing graph neural cellular automata with dynamic, learnable connectivity (Dec 2025), EvoNet's genetic-inspired self-evolving network structures (2025), knowledge-aware evolutionary graph neural architecture search, and LLM-guided self-evolving NAS (SEKI). ([Self-Organizing Dynamic Graph Neural Cellular Automata](https://www.ijcsejournal.org/self-organizing-graph-neural-cellular-automata/), [Knowledge-aware Evolutionary Graph Neural Architecture Search](https://arxiv.org/pdf/2411.17339), [SEKI](https://arxiv.org/pdf/2502.20422), [Dynamic nested hierarchies — Frontiers, 2026](https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2026.1804338/full))

So the "world first" framing in the external draft does not survive a literature check, and this ADR does not repeat it. See [LITERATURE.md](../LITERATURE.md) for the full source list. What this project actually stakes a novelty claim on is narrower and checkable: **no published or public work found (as of this search pass) combines ternary weight quantization + bounded, self-evolving graph topology + a tamper-evident, deterministic-replay audit ledger, purpose-built for provably air-gapped edge deployment.** That combination — not any single technique — is the bet.

**The other thing already real: aethyro.com.** aethyro.com is a live product (verified 2026-07-07) selling GH05T3/Avery under "your AI runs on your hardware, not theirs," with four genuinely live, paying tiers — Personal ($29/mo), CPA ($499/mo), Dev ($299/mo), Research ($199/mo) — plus Legal and Healthcare listed as waitlist-only "coming soon." This changes what "go-to-market" means for this project: NTG does not need to invent a customer base or pick a vertical to have value. Its first real value proposition is an **infrastructure-level upgrade to the four tiers that already have paying customers** — dramatically lower memory/compute footprint (ternary weights) on the exact same hardware those customers already run on — not a new vertical decision. The "provably sovereign, audit-ledger" story becomes the premium differentiator layered on top once/if Legal or Healthcare ship.

## Decision

1. **Build the engine, not a vertical.** This repository's job is to prove: a ternary-quantized compute core, a self-evolving graph topology on top of it, and a tamper-evident audit ledger around the whole thing — end to end, benchmarked, honestly reported. No vertical-specific product decision is made until this exists and has been measured on real hardware.
2. **Reuse proven work, don't reinvent it — and verify what "proven" actually means before relying on it.** The ternary compute core is built explicitly on the BitNet b1.58 quantization shape (absmean-style thresholding), not a from-scratch scheme. The audit ledger's plan was corrected after directly reading GH05T3's actual source (2026-07-08, see [ADR 0002](0002-safety-rails-for-self-modification.md) and [docs/EXPERIMENTS.md](../EXPERIMENTS.md)): ChronosLedger is real and reusable for its actual proven properties — fast mmap agent-state slots, lineage tracing via `parent_offset` — but it is **not** tamper-evident or hash-chained, contrary to what this ADR originally assumed. That missing piece (`kernel/src/ntg/chain.rs`) was built here once the gap was found. The self-modification engine's safety posture reuses the rails already specified for Firmament (see [ADR 0002](0002-safety-rails-for-self-modification.md), adapted from Firmament's ADR 0002) and the mutation/fitness concepts already running in GH05T3's GenesisThread/MutationEngine.
3. **aethyro.com is the platform, not a sales channel for one vertical.** Once the engine has a real, benchmarked win (lower memory footprint, comparable or better task performance vs. the current full-precision path), it targets *every* existing aethyro.com tier as an infrastructure upgrade first — not a single new vertical's greenfield sales motion. Legal/Healthcare (still "coming soon," no code, no customers — see Firmament ADR 0003 for that verified finding) remain a *later* option once the engine's provable-sovereignty story is real, not a precondition for shipping value.
4. **Firmament is superseded for this bet.** The founder's decision to build here instead of Firmament's kernel means Firmament's legal-vertical-first plan (ADRs 0001/0003 there) is no longer the active plan. Firmament's ADRs stay as historical record, not deleted. This should be marked in Firmament's own docs (tracked separately, pending founder confirmation) rather than left silently stale.
5. **No calendar-fixed roadmap.** The external draft proposed a rigid "85-day" / "29-41 day" schedule. This project uses phase gates instead (see [ROADMAP.md](../ROADMAP.md)): each phase ships behind full green CI, with real measurements recorded, before the next phase starts. Estimates are given as rough sizing, not commitments — consistent with "measure, don't assume."

## Consequences

- Every phase's benchmark claims must be measured on real hardware and recorded (including honest negative results), not asserted — same discipline already validated on the founder's `aetherflux-zero` project (PR #2 there is an honest negative depth-experiment result; PR #3 is a real measured 11% bits-per-character win from a BPE tokenizer change). This project should hold itself to that same bar.
- The kernel stays vertical-agnostic; nothing about "legal" or "healthcare" gets built into the core engine. Vertical-specific work (if any) is a top layer added later, per this ADR's decision 3.
- Marketing/product copy for aethyro.com about this engine follows the same claims discipline established for Firmament (ADR 0003 there): no capability claim ships ahead of the tested code that makes it true.
